## Final Documentation Only

- `docs/` holds finished, production-ready, professional documentation only — the kind you'd hand to
  a new team member or an external reader. Don't put drafts, in-progress notes, or planning material
  directly in `docs/`.
- Working notes, exploratory drafts, and anything still being figured out belong in `docs/scratch/`
  (gitignored — never committed). If asked to jot down notes or a rough plan under `docs/`, put it
  in `docs/scratch/` instead of `docs/` proper.
- When editing an existing file directly under `docs/`, keep it at that same finished quality bar —
  don't leave TODOs, placeholder sections, or half-written content in it.
